# 검 키우기 대장간

카카오톡 "검 키우기" 계열의 확률형 강화 게임입니다. 의존성 없는 HTML 파일 하나로
동작하며, 빌드 과정도 서버도 필요 없습니다.

```
index.html 을 브라우저로 열면 끝입니다.
```

웹사이트(GitHub Pages·Vercel 등)에 올리면 **구글 로그인 · 클라우드 자동 저장 · 서버 시간 기준
출석 · 랭킹**이 저절로 켜집니다. 서버는 Firebase(무료 Spark 요금제)를 씁니다.
아래 "온라인 (Firebase)" 을 보세요.

## 이 게임이 다른 점

강화 게임의 본질은 확률표입니다. 그래서 확률을 숨기지 않았습니다.

- **성공 / 유지 / 하락 / 파괴** 네 결과의 확률이 화면 중앙의 가로 바에 실제 비율
  그대로 그려집니다. 강화를 누르면 굴림값이 바 위를 두 바퀴 훑고 한 구간에 멈춥니다.
- 보호 아이템을 사면 확률 바가 **그 자리에서 다시 그려집니다.**
- **새 무기의 등급·종류 확률도 화면에 그대로 적혀 있습니다** (일반 60% · 희귀 25% · 영웅 10% ·
  전설 4% · 신화 1%, 검 40% · 도끼·지팡이·창·철퇴 각 15%).

## 한 자루를 끝까지 키우기

무기는 **부서지거나 팔 때만** 새로 뽑힙니다. 강화에 성공해도, 하락해도 같은 무기입니다.
모양과 이름은 끝까지 그대로이고, 단계가 오를수록 같은 무기가 눈에 띄게 자랍니다.

| 단계 | 변화 |
| --- | --- |
| 매 단계 | 조금씩 커지고, 빛과 입자가 강해지고, 속성 색이 짙어짐 |
| +5 | 빛이 흐르기 시작 (검은 칼날, 나머지는 머리 부분을 따라) |
| +8 | 룬이 새겨짐 |
| +12 | 빛줄기를 뿜음 |
| +16 | 별빛이 주위를 돎 |
| +20 | 무지개빛이 깃듦 |

변화가 깨어나는 순간에는 화면 가득 연출이 뜹니다. 하락하면 그 변화도 다시 잠듭니다.
등급이 높은 무기는 일부 변화를 처음부터 갖고 태어납니다 (영웅: 빛의 흐름·룬,
전설: 여기에 빛줄기·별빛, 신화: 전부). 무기 이름 아래에 "다음 변화 +8 · 룬 각인"처럼
다음 목표가 표시됩니다.

## 새 무기 뽑기 (부서지거나 팔 때)

| 등급 | 확률 | 판매가 | 생김새 |
| --- | --- | --- | --- |
| 일반 | 60% | ×1 | 평범한 무기, 금속 부분이 속성 색으로 물듦 |
| 희귀 | 25% | ×1.3 | 장식 있는 무기, 파란 픽셀 테두리 |
| 영웅 | 10% | ×2 | 화려한 무기, 보라 테두리, 처음부터 룬 |
| 전설 | 4% | ×4 | 속성마다 정해진 이름 있는 무기, 금빛 테두리·후광·별빛, 「천둥의 심판」 같은 별칭 |
| 신화 | 1% | ×10 | 속성마다 정해진 최고의 무기, 처음부터 무지개 테두리, 화면 흔들림 |

| 종류 | 확률 | 그림 (일반·희귀·영웅 / 전설·신화) | 예 |
| --- | --- | --- | --- |
| 검 | 40% | 36종 / 20종 (모든 속성) | 뇌전 그리핀의 대검, 종말의 화염도 |
| 도끼 | 15% | 19종 / 4종 | 화염 흑룡의 양날도끼, 얼음달 도끼 |
| 지팡이 | 15% | 4종 / 4종 | 서리 히드라의 마법 지팡이, 태양신의 황금 지팡이 |
| 창 | 15% | 14종 / 6종 (창·미늘창·도끼창·큰 낫) | 뇌전 악마의 창, 심해 군주의 삼지창 |
| 철퇴 | 15% | 24종 / 8종 (몽둥이·철퇴·가시철퇴·전투망치) | 맹독 와이번의 큰 가시철퇴, 변덕쟁이 무지개 망치 |

종류는 **모양만** 다르고 확률·가격은 같습니다. 전설·신화는 속성마다 정해진 무기라서, 그 속성·등급에
그림이 있는 종류 중에서만 뽑습니다(검은 모든 속성에 있고, 예를 들어 화염 전설은 검 또는 철퇴,
질풍·대지의 전설·신화는 검만 나옵니다). 이 업데이트 전에 갖고 있던 검은 모양·이름이 그대로입니다.

무기는 다음을 랜덤으로 조합해 만듭니다.

- **속성 10종** — 각자 고유한 상시 이펙트가 있습니다.
  화염(불티와 칼날을 핥는 불꽃) · 서리(눈송이, 서리 안개) · 뇌전(칼날에서 튀는 번개) ·
  암흑(보랏빛 연기와 검은 불꽃) · 성광(빛줄기, 반짝임) · 맹독(올라가는 거품, 떨어지는 독) ·
  질풍(무기를 감는 바람) · 대지(공전하는 바위 조각) · **성운(칼날 안에 은하수와 별똥별)** ·
  혈염(흘러내리는 핏방울)
- **무기 그림 139종** — 일반·희귀·영웅은 종류·등급별 그림 묶음에서 랜덤으로 고르고, 전설·신화는
  속성마다 정해진 무기입니다 (예: 화염 신화 "종말의 화염도"·"불꽃 군주의 도끼"·"지옥 군주의 홀",
  성광 신화 "질서의 별검"·"태양신의 황금 지팡이"·"망자 사냥꾼의 철퇴").
- **이름** — 일반~영웅은 `속성 + 생물 + 무기 이름` (예: "뇌전 그리핀의 대검", "서리 천사의 전투도끼"),
  전설 이상은 그 무기의 고유 이름과 별칭이 붙습니다

**도감**은 무기 종류마다 속성 10 × 등급 5 칸이고, 위쪽 탭(검·도끼·지팡이·창·철퇴)으로 바꿔 봅니다.
뽑은 적 있는 조합의 칸이 그 종류의 그림으로 밝혀집니다. 그 종류에 없는 전설·신화 칸은 "—" 로 비워 두고
세지 않으므로 모두 **192칸**입니다(검 50 · 도끼 34 · 지팡이 34 · 창 36 · 철퇴 38). 종류가 생기기 전의
도감 기록은 모두 검 도감으로 옮겨집니다.

## 무기 그림

무기 그림은 오픈소스 로그라이크 게임 **Dungeon Crawl Stone Soup** 의 픽셀아트 타일입니다.
작가들이 권리를 포기해 [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)
(퍼블릭 도메인)로 공개한 그림만 모아 둔 공식 배포본
[crawl/tiles](https://github.com/crawl/tiles) 의 `releases/Nov-2015` 에서 가져왔습니다.

- 원본 게임 저장소(crawl/crawl)에는 라이선스가 불분명한 그림이 섞여 있어서
  (`TILES_UNDER_UNKNOWN_LICENSE.md` 에 목록이 있음), **배포본에서만** 가져옵니다.
  빌드 스크립트가 그 목록과 파일 이름을 대조해 하나라도 겹치면 멈춥니다.
- 파일별 원본 경로와 커밋은 [`assets/weapons/CREDITS.md`](assets/weapons/CREDITS.md) 에 있습니다.
- 바꾼 점은 원본 타일에 그려진 바닥 그림자를 지운 것뿐입니다.

그림을 바꾸거나 더하려면 `tools/build_weapons.py` 의 `SWORDS`·`AXES`·`STAVES`·`SPEARS`·`MACES`,
`POOLS`(종류·등급별 묶음), `SIGNATURE`(종류·속성별 전설·신화)를 고친 뒤 다시 돌립니다. 그림자 제거,
끝·이펙트 자리(검은 코등이, 나머지는 머리가 시작되는 곳)·폭 계산, `assets/weapons/` 저장,
`index.html` 속 데이터 구역 갱신을 한 번에 합니다. 종류를 더하면 `index.html` 의 `KINDS` 에도
같은 순서로 더해야 합니다.

```
pip install pillow
git clone --depth 1 https://github.com/crawl/tiles /tmp/crawl-tiles
python3 tools/build_weapons.py /tmp/crawl-tiles
```

## 규칙

| 항목 | 내용 |
| --- | --- |
| 시작 골드 | 1,000,000 G |
| 단계 | +0 ~ +20 (21단계) |
| 성공 | 한 단계 상승, 같은 무기가 더 화려해짐 |
| 유지 | 실패했지만 단계 그대로 |
| 하락 | 한 단계 하락, 같은 무기 |
| 파괴 | 무기가 부서지고 +0 새 무기 (랜덤) |
| 판매 | 기본 판매가 × 등급 배수, +0 새 무기 (랜덤) |

+0~+3 은 실패해도 유지뿐이고, 하락은 +4부터, 파괴는 +6부터 시작합니다.

### 상점 (다음 1회에만 적용)

| 아이템 | 효과 | 가격 |
| --- | --- | --- |
| 축복의 주문서 | 성공 확률 +10%p | 강화 비용 × 3 |
| 파괴 방지권 | 파괴 → 하락으로 대체 | 강화 비용 × 4 |
| 장인의 손길 | 하락·파괴 → 모두 유지로 대체 | 강화 비용 × 7 |

출석 보상으로 받은 아이템은 **보관함**에 쌓이고, 상점 버튼에 "보유 1개 · 무료"로 표시됩니다.
원할 때 눌러서 다음 강화에 씁니다(보관함이 있으면 골드 대신 보관함에서 꺼냅니다).
파괴 확률이 0% 인 단계에서는 파괴 방지권을 쓸 수 없어서 아깝게 버려지지 않습니다.

골드가 떨어지고 팔 무기도 없으면 **풀무질**(+300 G) 버튼이 나타납니다.

## 출석 보상

하루에 한 번, 7일 주기로 받습니다. 화면 맨 위(골드 아래)에 있고, 받고 나면 한 줄로 접혀
내일 받을 보상을 알려 줍니다.

| 1일 | 2일 | 3일 | 4일 | 5일 | 6일 | 7일 |
| --- | --- | --- | --- | --- | --- | --- |
| 100,000 G | 200,000 G | 축복의 주문서 | 400,000 G | 파괴 방지권 | 600,000 G | 장인의 손길 + 1,000,000 G |

- **하루 빠져도 이어집니다.** `ATTEND_RESET_ON_MISS` 를 `true` 로 바꾸면 빠진 날 1일차로
  돌아가는 "연속 출석"이 됩니다.
- 7일을 채우면 다시 1일차부터입니다.
- 초기화해도 출석 기록은 유지됩니다(초기화로 같은 날 또 받는 걸 막기 위해서).
- 자정이 지나거나 다른 탭에 갔다 돌아오면 버튼이 다시 켜집니다.
- 어디서 여느냐에 따라 기준 시계가 다릅니다.

| 여는 곳 | 기준 | 날짜를 바꾸는 꼼수 |
| --- | --- | --- |
| 웹사이트 (온라인) | **서버 시간 (한국 시간 자정)**, 구글 로그인 필요 | 막힘 — 서버 규칙이 거부 |
| 파일로 열기 · Claude 아티팩트 | 이 기기 시계 | 시계를 뒤로 돌리는 건 막지만, 앞으로 돌리는 건 못 막음 |

웹사이트에서는 로그인하지 않으면 출석을 받을 수 없고, 서버에 연결되기 전이나 연결에 실패한
동안에도 버튼이 잠깁니다(기기 시계로 받은 보상이 계정으로 올라가는 길을 막기 위해서). 온라인
출석은 하루 빠져도 이어지며, `ATTEND_RESET_ON_MISS` 는 기기 시계 모드에만 적용됩니다.

## 진행 상황 저장

1. **자동 저장** — 행동할 때마다 `localStorage` 의 `forge-sword-kr-v4` 에 저장됩니다.
2. **저장 코드** — `SWORD4-<압축된 진행값>-<체크섬>`. 들고 있는 무기, 종류별 도감, 보관함,
   출석 기록까지 함께 옮겨집니다. 다른 기기에서 "저장 코드 불러오기"에 붙여넣으면 그대로
   이어집니다.
3. **구글 계정 저장** (웹사이트) — 로그인하면 바뀔 때마다 2초 모아서 Firebase 에 올립니다.
   다른 기기에서 같은 계정으로 로그인하면 이어집니다. 아래 "온라인 (Firebase)" 참고.
4. **아티팩트 클라우드 동기화** (선택, 기본 꺼짐) — 아티팩트로 배포할 때
   `capabilities: {db:{}, user:{}}` 를 선언하면 사용자별 비공개 문서에 자동 저장됩니다.
   단, `db` 를 선언한 아티팩트는 공개 링크로 공유할 수 없습니다.

**v4 에서 모두 처음부터 다시 시작했습니다** (시작 골드 1,000,000 G · 출석 보상 추가와 함께).
예전 저장(`forge-sword-kr-v2`·`v3`)은 읽지 않고, 예전 저장 코드(`SWORD3-` 이하)는
"예전 버전 코드"라고 안내하며 거절합니다. 예전 저장을 지우지는 않으므로, 되돌리려면
`SAVE_KEY` 를 바꾸면 됩니다.

## 온라인 (Firebase)

`index.html` 을 웹사이트에 올리면 아래 기능이 켜집니다. 파일로 열거나 Claude 아티팩트에서 열면
(바깥 서버와의 통신이 막혀 있으므로) 지금처럼 이 기기에만 저장하는 모드로 동작합니다.

| 기능 | 내용 |
| --- | --- |
| 구글 로그인 | 화면 위 구글 공식 버튼("Google 계정으로 로그인"). 사이트 주소가 OAuth 클라이언트에 등록돼 있지 않으면 예전 "구글로 로그인" 버튼(Firebase 창)이 대신 나옵니다 — 아래 "구글 로그인 버튼". 카카오톡 등 앱 안 브라우저는 구글이 로그인을 막으므로 "다른 브라우저로 열기"를 안내합니다 |
| 카카오톡에서 열기 | 카카오톡에서 링크를 열면 처음 한 번 크롬·사파리로 자동으로 넘깁니다. 카카오톡 안에서 하던 진행이 있으면 주소 끝(`#carry=저장 코드`)에 실어 함께 옮기고, 브라우저에 이미 다른 진행이 있으면 어느 쪽을 쓸지 묻습니다. "카톡에서 계속하기"를 고른 폰은 더 이상 자동으로 넘기지 않습니다(카카오톡 안에서는 로그인·출석·랭킹 참여가 안 됨) |
| 클라우드 자동 저장 | 로그인하면 계정에 저장되고, 새 기기에서 로그인하면 자동으로 이어집니다. 양쪽에 다른 진행이 있으면 어느 쪽을 쓸지 묻습니다 |
| 서버 시간 출석 | 한국 시간 자정 기준 하루 한 번. 서버가 기록을 받아 준 뒤에만 보상을 줍니다 |
| 랭킹 | 최고 강화 단계 → 최고 보유 골드 순 상위 20명. 그 기록을 세운 무기 이름이 함께 나옵니다. 초기화해도 최고 기록은 내려가지 않습니다. 랭킹 이름은 처음엔 "대장장이1234" 같은 별명이고 바꿀 수 있습니다(구글 이름·메일은 올라가지 않음) |

한 기기를 여러 사람이 쓸 때: 다른 계정으로 로그인하면 앞사람의 진행을 물려받지 않고 그 계정의
기록(없으면 새 판)으로 시작합니다.

### 처음 한 번 설정하기 (Firebase 콘솔)

`index.html` 의 `FIREBASE_CONFIG` 에는 이미 `sword-forge` 프로젝트 값이 들어 있습니다.

1. **Authentication → 로그인 방법 → Google** 을 사용 설정
2. **Firestore Database → 데이터베이스 만들기** — 위치 `asia-northeast3 (서울)`, 프로덕션 모드
3. **Firestore Database → 규칙** 탭에 저장소의 [`firestore.rules`](firestore.rules) 내용을
   통째로 붙여넣고 **게시**
4. 게임을 올릴 웹사이트를 정한 뒤, **Authentication → 설정 → 승인된 도메인**에 그 주소를 추가
   (예: `ys-prog704.github.io`, `내프로젝트.vercel.app`)

요금제는 무료 **Spark** 그대로 두면 됩니다. 결제 카드를 등록할 필요가 없고, 한도를 넘으면 돈이
나가는 대신 그날만 멈춥니다.

### 구글 로그인 버튼 (Google Cloud 콘솔, 한 번)

Firebase 의 로그인 창(`signInWithPopup`)은 `firebaseapp.com` 을 거쳐 돌아오는데, 아이폰 사파리에서는
첫 로그인 때 "Unable to process request due to missing initial state" 화면에서 자주 끊깁니다(창을 닫고
다시 누르면 됨). 그래서 구글이 직접 띄우는 공식 버튼(Google Identity Services)을 씁니다. 구글 창 안에서
로그인이 끝나고 결과(ID 토큰)만 이 페이지로 돌아와 `signInWithCredential` 로 Firebase 에 넘기므로
그 문제가 없습니다.

이 버튼은 사이트 주소가 Firebase 가 만든 OAuth 클라이언트의 **승인된 JavaScript 원본**에 있어야
나타납니다.

1. [Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보](https://console.cloud.google.com/apis/credentials?project=sword-forge)
2. **OAuth 2.0 클라이언트 ID** 의 **Web client (auto created by Google Service)** 를 눌러 열기
3. **승인된 JavaScript 원본 → URI 추가** 에 `https://ys-prog704.github.io` (끝에 `/` 나 경로 없이) → **저장**

반영까지 몇 분 걸릴 수 있습니다. 등록 전에는 구글이 버튼을 그려 주지 않는데(버튼 iframe 이 0×0),
게임은 이를 알아채고 예전 버튼을 대신 보여 주며, 그 창이 끊긴 채 돌아오면 "한 번 더 눌러 주세요"라고
안내합니다. 클라이언트 ID 는 `index.html` 의 `GOOGLE_CLIENT_ID` 에 있습니다(공개되는 값).

### 웹사이트에 올리기

저장소를 그대로 올리면 됩니다. 빌드는 없고, 실제로 필요한 파일은 `index.html` 하나입니다.

- **GitHub Pages** — 저장소가 공개여야 합니다(무료 요금제 기준). 저장소 Settings → Pages →
  Source "Deploy from a branch" → Branch 를 고르고 폴더는 `/ (root)` → Save. 주소는
  `https://<계정>.github.io/<저장소>/` 이고, 그 브랜치에 올릴 때마다 1~2분 뒤 저절로 바뀝니다.
  저장소의 빈 파일 `.nojekyll` 은 GitHub Pages 가 파일을 가공하지 않고 그대로 내보내게 합니다.
- **Vercel · Netlify** — 비공개 저장소도 됩니다. GitHub 계정으로 가입 → 이 저장소를 Import →
  Framework 는 "Other", 빌드 명령은 비워 두고 Deploy.

### 서버에 남는 것과 보안

| 위치 | 내용 | 누가 |
| --- | --- | --- |
| `saves/{uid}` | 저장 코드(`SWORD4-…`)와 저장 시각 | 본인만 읽기·쓰기 |
| `attend/{uid}` | 마지막 출석 시각(서버 시간), 다음 칸, 총 출석일 | 본인만, 하루 한 칸씩만 |
| `ranking/{uid}` | 랭킹 이름, 최고 단계, 최고 골드, 무기 이름·등급·속성 | 누구나 읽기, 본인만 쓰기 |

- `FIREBASE_CONFIG` 의 `apiKey` 등은 **웹페이지에 공개되도록 만들어진 값**입니다(비밀번호가
  아닙니다). 데이터를 지키는 것은 `firestore.rules` 입니다. GitHub 가 이 값을 "비밀 키"라고
  경고할 수 있지만 오탐입니다. 원하면 Google Cloud 콘솔에서 이 키를 내 웹사이트 주소에서만
  쓰이도록 제한할 수 있습니다(이때 `sword-forge.firebaseapp.com` 도 함께 넣어야 로그인이 됩니다).
- 서비스 계정 키(비공개 키 JSON)는 이 게임에 필요 없습니다. 절대 저장소에 올리지 마세요.
- 출석은 서버 시간과 규칙으로 꼼수를 막습니다. 반면 강화 결과는 브라우저에서 계산하므로,
  개발자 도구를 다룰 줄 아는 사람이 랭킹 숫자를 조작하는 것까지는 막지 못합니다(규칙은 0~20단계
  같은 범위만 검사합니다). 친구끼리 즐기는 랭킹으로 생각해 주세요.

### 개발: 로컬 에뮬레이터로 시험하기

`127.0.0.1` 이나 `localhost` 에서는 실제 Firebase 에 붙지 않습니다. 주소 끝에 `?emu=1` 을
붙이면 Firebase Local Emulator Suite(인증 9099, Firestore 8080, 프로젝트 `demo-sword-forge`)에
붙고, 개발자 콘솔에서 `__emuLogin('alice', 'Alice')` 로 가짜 구글 계정 로그인을 할 수 있습니다.

```
npm i -g firebase-tools        # Java 11 이상 필요
firebase emulators:start --only auth,firestore --project demo-sword-forge   # 저장소 폴더에서
python3 -m http.server 8000    # → http://127.0.0.1:8000/index.html?emu=1
python3 tools/test_rules.py    # 보안 규칙 시험 (출석 꼼수·남의 기록 쓰기·범위 밖 값 등 28가지)
```

에뮬레이터는 저장소의 `firebase.json` 을 따라 `firestore.rules` 를 읽습니다.

## 밸런스 수정하기

- `LEVELS` — 단계별 성공/하락/파괴 확률, 시도 비용, 기본 판매가
- `RARITIES` — 등급별 뽑기 가중치(`w`, 1000분율), 판매가 배수, 빛의 세기
- `FEATS` — 성장 변화가 깨어나는 단계(`at`)와, 처음부터 갖고 태어나는 등급(`rar`)
- `ATTEND` — 출석 보상표(`gold`, `item`), `ATTEND_RESET_ON_MISS` — 빠진 날 처리
- `START_GOLD` — 시작 골드
- `ELEMENTS` — 속성별 색과 이펙트
- `KINDS` — 무기 종류별 뽑힐 비율(`w`, %)
- 어떤 무기 그림이 어느 종류·등급·속성에 나오는지는 `tools/build_weapons.py` 에서 정합니다 (위 "무기 그림")

## 구현 메모

- 순수 HTML + CSS + 바닐라 JS. 프레임워크, 번들러, 이미지 파일 없음.
  온라인 기능의 Firebase SDK 는 웹사이트에서만 `import()` 로 그때 불러옵니다.
- 무기 그림(32×32 PNG)은 `data:` URI 로 `index.html` 안에 들어 있어서 파일 하나로 동작합니다.
  `<canvas>` 에 흐림 없이(nearest-neighbor) 확대해 그리고, 캔버스 실제 픽셀 수를 화면 크기 ×
  기기 배율에 맞춰 픽셀이 뭉개지지 않게 합니다.
- 일반~영웅 무기는 회색 금속 픽셀만 속성 색으로 물들입니다(금빛 손잡이·나무 자루·보석은 그대로).
  단계가 오를수록 진해집니다. 등급 테두리는 그림을 한 픽셀 부풀린 모양에 색을 칠해 그립니다.
- 빌드 때 계산한 칼끝·코등이·칼날 폭으로 불꽃·번개·룬·빛의 흐름이 칼날을 따라 나옵니다.
  발광과 입자는 `lighter` 합성으로 겹칩니다.
- 무기의 그림·이름은 seed·등급·종류로만 정해지고, 크기·빛·입자·장식은 현재 단계로
  계산합니다. 그래서 저장에는 seed·속성·등급·종류 네 숫자만 남기면 됩니다(검은 종류를 적지 않아서
  예전 저장 코드와 모양이 똑같습니다).
- 도감의 미니 그림도 같은 렌더러를 쓰며, 첫 화면을 막지 않도록 한 프레임에 몇 개씩
  나눠 그립니다.
- 효과음은 WebAudio 로 합성합니다. 등급이 높을수록 팡파레 음이 길어집니다.
- `prefers-reduced-motion` 을 존중합니다. 이 경우 무기는 멈춘 그림으로 보입니다.
